# AI写作降重全攻略：从绝望到8.5%的逆袭之路

> これはAIで生成された論文テキストを「人間らしい」形に変換するための切実な経験談です。

## 前置き

事情はこうです。先日、AIを利用して論文を作成したところ、検査ツールを実行した結果、78%の内容が赤色に表示されました。その気持ちは、試験で不正行為が発覚した時のようで——困惑、慌て立ち、そして深い自己疑問に陥りました。

しかし、降参することはできない！そこで長い再撰作の道が始まった。数回の厳しい奮闘の後、最終的に AIの割合を8.5％にまで引き上げることができた。この記事では全過程を記録する。同じ悩みを抱える仲間の助けになることを願ってる。

---

## 第一章：心構えの構築

まず、一つの事実を理解する必要がある：**AIによる執筆には痕跡がある**。AIで書いた論文が検出に合格しないわけではないが、その「完璧な機械的な感じ」は容易に認識される。

AIが書いたテキストには通常どのような特徴があるか？
- 文の長さが均一で、まるで軍隊の陣形のようだ
- 語彙が単調で、頻出語が繰り返し登場する
- 論理があまりにも明確で、人間の書き方の「余計な話」や「遠回り」が欠けている
- 「まず、次に、最後に」といった整然とした構成が過度に使われている

だから、論文を変更する核心的なアプローチは：**この完璧さを破り、人間の書き方のランダムさと不規則さを増やす**ことだ。

## 第二章：私の論文変更の方法

### 2.1 前期准备

必要なツールは以下です：
1. **検出レポート**：AI検出のHTMLレポートをエクスポートするもの
2. **原文文書**：元の論文docxファイル
3. **有能なAI**：使用しているのはClaude Opusモデルで、丁寧に設計されたフレーズを使用しています

### 2.2 核心フレーズ

これは実戦から抽出したフレーズで、実際に有効であることが確認できています：

```markdown
# 役割
あなたは経験豊富な学術編集者であり、人間のライティングスタイル模倣の専門家です。あなたの任務は、提供された学術文を書き直し、AI検出ツールでの認識率を低減させつつ、原文の意図と専門的な正確性を保つことです。

# 目標
指定されたテキストを、より高い「困惑度」（Perplexity）と「爆発性」（Burstiness）を持つバージョンに書き直し、アルゴリズム生成の標準的なテキストよりも人間が自然に書いた記事のように読まれるようにします。

# 制約
1. 核心情報は変わらない：技術パラメータ、データ、核心結論、専門用語の定義を変更してはいけません。
2. AIの特徴を避ける：過度に整った対比表現や標準的な「まず…次に…最後に」の構造、過度に簡潔で効率的な表現は使わないこと。
3. 学術性を保つ：AIの割合を下げるものの、学術論文としての厳密性を保ち、あまりに口語的にならないこと。

# 手法（以下の戦略を必ず適用）
1. 語彙の多様化：
   - 頻繁に使われる動詞を同義語に変える（例：「针对」を「就…を研究する」に変える、「实现」を「実施」または「達成」に変える、「依托」を「依拠」または「利用」に変える）
   - 適切な修飾語を追加する（「関連する」「具体的な」「多数の」「一連の」など）

2. 文構造の再構築：
   - 長い文を二つの短い文に分割するか、コンマで区切って間隔を増やす
   - 語順を変える：一部の能動態文を受動態文に変えるか、状況語の位置を変える
   - 接続詞を増やす：より自然な論理接続詞を使う（「こうなると」「同時に」「鑑みて」「具体的には」「この基準の上で」など）で、単一の順序語を避ける

3. 「人間の痕跡」の追加：
   - 説明的文を適切に追加し、原文が含んでいる場合の概念について簡潔に補足説明をする
   - 人間のライティングのわずかな冗長さを模倣する（例、動詞の後に「作業」「操作」「状況」などの名詞語尾を加える）

4. リズムの管理：
   - 段落内の文の長さがバラバラになるようにし、全ての文が同じ長さになるのを避ける
```

### 2.3 実戦ワークフロー

私はこのように操作します：

**第一ステップ：AIのマークされた断片を抽出する**

検査報告はHTMLファイルであり、CSSクラス`cl3`を使用してAI生成と認定されたすべてのテキストがマークされています。私はPythonのBeautifulSoupを使ってこれらのフレーズを抽出し、JSON形式に変換して利用しています。

**第二ステップ：原文の文脈をマッチングする**

どの文が問題があるかだけでは不十分です。この文の前後で何が語られているかも知る必要があります。AIの改変時には文脈が正確な語彙を提供するため、元の論文のdocxファイルも同時に読み取り、マークされた各フレーズにそれが属する章と前後の段落を付与します。

**第三ステップ：グループ化して並行改変**

78箇所のマーク、多ければ言い、少ければ言わない。一つ一つ変更するのは疲れる。そこでこれらの断片を4つのグループに分け、4つのAIスマートアンドルで並行処理した。

**第四ステップ：対照文書の作成**

改稿完了後、対照文書を作成します。左側に原文、右側に改稿版があります。これにより、意味が変わらないかを一つ一つ手作業で確認し、その後で手動で論文に代入できます。

**第五ステップ：不備の検証**

ここに落とし穴があります：スマートアバターが一部の断片を漏らす可能性があります。ですので、完成した後必ず数を確認し、正しいかどうかをチェックしてください。何か不足していることがわかったら、別途もう一度実行してください。

## 第三章：実戦技術のまとめ

### 3.1 語彙面

| 原表达 | 替换方案 |
|--------|----------|
| 针对... | 就...展开研究 |
| 实现 | 落实、达成、完成 |
| 依托 | 依靠、借助 |
| 确保 | 保证、确保...的顺利实现 |
| 提升 | 提高、增强、改善 |

### 3.2 句式层面

- **打散长句**：遇到那种四五行不带喘气的长句，果断拆！
- **调整语序**：主谓宾改成被动，或者把状语搬到前面
- **替换连接词**：别总用"首先/其次/最后"，试试"如此一来"、"与此同时"、"在此基础上"、"具体来讲"

### 3.3 增加人类痕迹

これが最も重要なステップです！人間の文章にはAIにはない「悪い習慣」がいくつあるのでしょうか？

- たまに無意味な話や繰り返しの説明
- 文の途中で突然別の文を追加する
- 括弧や破折符を使って余計な話を挟む
- 動詞の後に不要に見える名詞を加える（「関連する作業を開始する」という形で「開始」を使わない）

### 3.4 リズムのコントロール

AIが書いた文章は式典のようで、文の長さが整然としています。人間が書いた文章は交響曲のようで、高い部分も低い部分も、長い部分も短い部分もあります。**必ず文の長さをバラバラに保つ**ことです。

## 第四章：我的血泪教训

1. **不要贪多**：最初はすべての断片を一度に修正しようとしないこと。間違いが生じやすいので、段階的に行うこと
2. **検査完整性**：AIは実際に書き落しが生じる！各段階を終えたら数を数えること
3. **人工検査**：修正後は必ず自分で読み直すこと。意味が変わっていないか確認すること
4. **忍耐**：このプロセスは退屈だが、卒業のために我慢する
