## 起案の経緯

海外の顧客からメッセージが来た：**「今夜9時に生産環境の問題を相談できますか？」**

担当者が見て、私に伝えてくれた：「顧客が今夜9時に生産の問題を処理したいと言っています。」

私は思った、夜の9時だから、食事を終えた後少し休んで、その時にコンピュータを開いて処理すればいい。嬉しいことだ。

**その後は、もう終わりです。**

## タイムゾーンの致命的な落とし穴

状況は以下の通りです：

- 顧客はアメリカにいるため、**アメリカ時間の今夜9時**ということです
- アメリカの夜9時 = **中国の朝9時**（東部時間 ET, UTC-5）
- 専門家が伝えた時は「今夜9時」とだけ言って、タイムゾーンは明記していません
- 私は当然のように**中国時間の今夜9時**と理解しました

時間軸：

```
アメリカの顧客の視点：
  "今夜9時" → アメリカ東部時間 21:00 → 北京時間 翌日 09:00 ✅

私の理解：
  "今夜9時" → 北京時間 21:00 → アメリカ東部時間 08:00 ❌

実際の差：全く12時間！
```

## 災害現場

翌日の朝、目覚まし時刻が9:45に鳴り、私はぼんやりと起き上がり、10時に出勤する準備をした。

携帯を開いてみると——メッセージ一覧が爆発した：

> 顧客（3時間前）：Hi, I'm ready, are you there?
>
> 顧客（2時間前）：Hello?
>
> 顧客（1時間前）：I guess we'll have to reschedule...

**顧客は1時間以上待って、その後寝に行った。**

私は9:45になってようやく起きた。

ああああああああああ！！！

## 振り返り：問題はどこにあるか

### 1. 時区のコンテキストが情報伝達で失われている

海外の顧客が「tonight 9pm」と言ったが、このtonightは彼のtonightであり、私のtonightではない。しかし専門家の伝達の後、中国語の「今晚9点」になってしまい、時区情報が失われてしまった。

### 2. 国境を越えた協力にあたって、デフォルトの前提が異なる

- 顧客はデフォルトで彼がアメリカにいることを知っているため、話しているのはアメリカ時間である
- 私はデフォルトで「今夜」とは中国時間の今夜を指している
- 専門家もこのタイムゾーン差の問題に気づいていない可能性がある

### 3. 二次確認は不要

もし当時「北京時間かアメリカ時間かを確認してください」ともっと尋ねていたら、この事故は起こらなかっただろう

## よく見られる時区対照表（救命表）

海外の顧客と取引する際、この表を頭に刻み込む必要があります：

| アメリカの時区 | 北京時間との差 | 彼が夜9時と言う = 私たちの |
|---------|------------|-------------------|
| 東部時間 ET (UTC-5) | -13時間 | 翌日の朝10:00 |
| 中部時間 CT (UTC-6) | -14時間 | 翌日の朝11:00 |
| 太平洋時間 PT (UTC-8) | -16時間 | 翌日の午後13:00 |
| 夏時間ではさらに1時間早い | | |

> 注：アメリカの夏時間（3月～11月）では時差が1時間少なくなります。例えば、東部の夏時間 EDT (UTC-4)では、夜9時 = 北京時間の翌日の朝9:00です。

そのため今回の状況は夏時間の間、アメリカ東部の夜9時 = 北京時間の朝9時であり、私は10時から仕事を始める...

## 涙と血の教訓

### 国境を越えたコミュニケーションで必ず実施すべきこと：

**常に時区を記載する。** あなたが言うか相手が言うかに関わらず、時間の後に時区を付ける必要がある。「今夜9時 ET」または「北京時間の明日の朝9時」、多くの文字を書くことで助かる。

**UTCをアノタットポイントとして使用します。** チーム内ではUTC時間を統一してコミュニケーションを行い、それぞれを現地時間に変換します。例えば `UTC 01:00` = 北京 09:00 = 美东 20:00（夏時間）。

**情報の伝達は完全である必要があります。** 専門家や仲介者が時間を伝える際には、元の時区情報を必ず含めなければなりません。「顧客がアメリカ東部時間の今夜9時と言っているので、変換すると明日の朝9時になります」。

**カレンダーリマインディングを設定します。** 異なる時区の会議時間を受け取った後、すぐにカレンダーにイベントを作成し、システムが自動的に時区を変換するようにします。Google CalendarやOutlookは複数の時区表示をサポートしています。

**重要な会議は事前に確認します。** 会議の数時間前に確認メッセージを送ります：「 tomorrowのET 9pm / 北京時間9amでの会議を確認します、正しいですか？」

## 最後に

タイムゾーン問題は一見小さく見えるが、国境を越えた協力においては実際に隠れた危険な存在だ。タイムゾーンが異なるため、「今夜」という二文字が半日もの差を生むこともある。

この経験から、私は深く理解した——**国境を越えたコミュニケーションにおいて、タイムゾーンが記載されていない時間は爆弾のようなものだ**。

この記事を読む皆さんが、私の過ちを繰り返さないことを願っている。覚えておいてほしいのは、海外の顧客が言う「今夜」は、おそらくあなたの「明早く」を意味しているということだ。

> 現在私の仕事の習慣は、海外の顧客に関わる時間があれば、最初の反応はタイムゾーン変換器を開くことです。もう一度確認するくらいなら、「顧客が寝ていて自分が起きている」という絶望的な状況を経験するよりはましです。
